## Objective

This guide explains how to **export logs stored in the Logs Data Platform (LDP)**.  
It presents several methods to export logs through the OpenSearch API. 


## Requirements


- you are already sending logs on a stream you own [see the quick start tutorial](/pages/manage_and_operate/observability/logs_data_platform/getting_started_quick_start)
- you have access to the port 9200 of your cluster (head to the **Home** page in the Logs Data Platform section of OVHcloud control panel to know the address of your cluster)


## Introduction

Exporting logs is a common need when you want to analyse data outside the LDP ecosystem, feed it to external BI tools. For archiving, we provide [another solution](/pages/manage_and_operate/observability/logs_data_platform/archive_cold_storage/).  
We will explain how to use Logstash and fluent-bit to export logs. 


## Alias naming conventions

When you create an OpenSearch alias that points to a Graylog stream, the **only customize part is the suffix after -a-.** Ex: `ldp-ti-98765-a-your_suffix`**.  
The remainder of the name is generated by the platform:

| IAM status | Generated part | Full alias example |
|------------|----------------|--------------------|
| **IAM disabled** (legacy authentication) | your *username* (e.g. `logs-ab-12345`) | `logs-ab-12345-a-logs-export` |
| **IAM enabled** | the *service identifier* (e.g. `ldp-ti-98765`) | `ldp-ti-98765-a-logs-export` |

The `<suffix>` part (here `logs-export`) is a free‑form string you choose to describe the purpose of the alias.  


## Create a stream alias

1. Log in to the [OVHcloud Control Panel](/links/manager).  
2. Open the **Alias** panel and click **Add an alias**.  
3. Choose a suffix.  
4. Add a description and save the alias.  
5. Click the **…** menu on the right of the newly created alias and select **Attach content to the alias**.  
6. Select the Graylog stream(s) you want to export and confirm.

The alias now points to the underlying OpenSearch alias that stores the logs of the chosen stream.

## Export logs with Logstash

### Requirements

| Requirement | Details |
|-------------|---------|
| Logstash ≥ 8.0 | Install Logstash on a host that can reach your LDP cluster. |
| Java 8 or 11 | Required by Logstash. |
| OpenSearch endpoint | `https://<ldp‑cluster>.logs.ovh.com:9200` |
| Authentication | Basic user/password **or** IAM Bearer token (see the [IAM Faq](/pages/manage_and_operate/observability/logs_data_platform/iam_presentation_faq/)). |
| Alias name | The alias created in the previous step (e.g. `logs-ab-12345-a-logs-export`). |

### Install Logstash and the OpenSearch plugins

```bash
# Download Logstash (tarball example)
wget https://artifacts.elastic.co/downloads/logstash/logstash-8.8.2-linux-x86_64.tar.gz
tar -zxvf logstash-8.8.2-linux-x86_64.tar.gz
cd logstash-8.8.2

# Install the required plugins
bin/logstash-plugin install logstash-output-opensearch
bin/logstash-plugin install logstash-input-opensearch
```

### Logstash pipeline

Create a file `pipeline.conf` (any location, e.g. `config/pipeline.conf`):

```ruby
input {
  opensearch {
    hosts => ["https://<ldp-cluster>.logs.ovh.com:9200"]
    # Use basic auth or IAM token
    user => "<username>"
    password => "<password>"
    # If you use IAM, replace the two lines above with:
    index => "<alias-name>"
    schedule => "*/5 * * * *"          # run every 5 minutes
    query => '{"query":{"bool":{"must":[{"match_all":{}}],"filter":[{"range":{"timestamp":{"gte":"now-1d"}}}]}}}'
    scroll => "5m"
    ssl => true
    ssl_certificate_verification => false
  }
}

filter {
  # Optional: convert the timestamp to a readable format
  date {
    match => ["timestamp", "ISO8601"]
    target => "timestamp"
  }
}

output {
  csv {
    path => "/var/log/ldp/export-%{+YYYY-MM-dd}.csv"
    fields => ["timestamp", "host", "log.level", "message"]
    csv_options => {"col_sep" => "," "row_sep" => "\n"}
    gzip => false
    create_if_deleted => true
    flush_interval => 2
  }
}
```

#### Explanation of the `csv` options

| Option | Required | Description |
|--------|----------|-------------|
| `path` | Yes | Destination file; supports date patterns (`%{+YYYY-MM-dd}`). |
| `fields` | Yes | Ordered list of event fields to write. Missing fields become empty strings. |
| `csv_options` | No | Ruby CSV options (e.g. custom column separator). |
| `gzip` | No (default `false`) | Compress the output file. |
| `create_if_deleted` | No (default `true`) | Re‑create the file if it disappears while Logstash runs. |
| `flush_interval` | No (default `2` seconds) | How often Logstash flushes data to disk. |

### Run the pipeline

```bash
# From the Logstash root directory
bin/logstash -f config/pipeline.conf --config.reload.automatic
```

Logstash will connect to the OpenSearch endpoint, read the documents that belong to the alias defined above, and write the selected fields to a daily CSV file under `/var/log/ldp/`.

## Next steps

* **Add more fields** to the `fields` list to enrich the CSV export.  
* **Enable compression** with `gzip => true` for large exports.  
* **Combine with additional Logstash filters** (e.g., `grok`, `geoip`) to transform data before writing.  
* **Alternative extraction method** – a second section will describe how to use the OpenSearch `_search` API together with a CSV exporter to achieve the same result without Logstash.

For more details on the OpenSearch input plugin, see the official documentation: <https://docs.opensearch.org/latest/tools/logstash/read-from-opensearch/>.  
The CSV output plugin reference is available at: <https://www.elastic.co/guide/en/logstash/current/plugins-outputs-csv.html>.
